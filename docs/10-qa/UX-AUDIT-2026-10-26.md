# Revisión de UI y experiencia de usuario — UX-001

## Criterio de diseño

Se revisó el frontend local `investor/comunia-investor-web`: su navegación
agrupada, contraste entre sidebar y contenido, jerarquía de tarjetas, espaciado
y adaptación móvil son referencias útiles para este producto. Se conservaron
Next.js, Tailwind, shadcn y la resolución de marca de NewSaaS. No se copiaron
colores de COMUNIA, datos, dependencias ni contratos de Investor.

La evaluación es una revisión experta de código e interfaz con datos demo;
todavía no es una prueba de usabilidad con personal de una clínica.

## Implementado

| Superficie                     | Mejora                                                                                                                                                                                                           |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shell de staff                 | Navegación agrupada por tarea, iconos, sección activa incluso en detalles, encabezado con contexto y ancho de lectura limitado. Se eliminaron controles de relleno.                                              |
| Móvil                          | Menú modal nativo con foco contenido, Escape, cierre al navegar, bloqueo del scroll del fondo y enlace para saltar al contenido.                                                                                 |
| Sistema de UI                  | Input, Badge, Skeleton, Spinner e iconos compartidos; Button con estado de carga y Card con radio semántico. Sin nuevas dependencias.                                                                            |
| Feedback                       | Barra de actividad para navegación/carga inicial/mutaciones; skeletons de ruta y listas; estados vacíos, búsqueda sin resultados y errores recuperables. Los refrescos de datos ya visibles no activan la barra. |
| Dashboard                      | Métricas existentes con jerarquía y acciones hacia agenda, pacientes, POS y reportes. Sin indicadores inventados ni cálculos monetarios nuevos.                                                                  |
| Clientes, pacientes y catálogo | Encabezados, filtros/búsqueda, filas adaptables, estados y acciones consistentes. La búsqueda es local sobre los resultados que ya devuelve la API.                                                              |
| Paciente                       | Corrección de superposición entre el nombre del responsable y sus botones en móvil. El detalle clínico mantiene sus operaciones existentes.                                                                      |
| Ingreso y salida               | Pantalla de acceso adaptable, campos y envío con feedback. La salida usa una ruta BFF privada hacia la revocación existente y muestra error si no puede confirmarla.                                             |
| Marca / CSP                    | El estilo validado reutiliza el nonce del documento inicial durante navegación RSC. El ingreso exitoso abre un documento autenticado completo. No se relajó CSP ni se admitió CSS arbitrario.                    |

El resto de los módulos recibe el shell y las bases compartidas; no se considera
rediseñado por completo cada formulario o flujo del sistema. El portal conserva
su interfaz: solamente comparte la corrección del nonce de marca.

## Seguimiento — UX-002

Actualización del 2026-10-27: la instancia correcta ya fue iniciada y la
búsqueda acotada por paciente/responsable está implementada en [[UX-003]]. La
evidencia actual y las correcciones de teclado/importes están en
[[UX-VALIDATION-2026-10-27]]; las observaciones del 2026-10-26 que siguen son
históricas y no describen el estado actual de esa instancia.

La siguiente iteración queda registrada en
[[UX-002-es-py-and-clinical-workflows]]:

- Se acepta `es-PY` para presentación de staff en
  [[DEC-080-staff-locale-es-py]]. El shell, agenda, ficha clínica y POS pasan
  por una primera localización; el Portal y los módulos operativos restantes no
  se consideran traducidos.
- Los importes de venta conservan sus cadenas decimales y la moneda de la API.
  La presentación agrupa dígitos en Paraguay y los campos aceptan coma decimal
  exacta; la suma de cobros mantiene aritmética decimal por cadena.
- El cierre clínico pide confirmar y guardar el borrador antes de hacer
  inmutable la consulta. La revisión del POS muestra el total y los pagos antes
  del comando existente. Las confirmaciones usan `<dialog>` nativo con foco,
  Escape, cancelación, estado pendiente y errores de la operación.
- La agenda puede abrir la ficha desde un turno, pero no puede seleccionar o
  identificar pacientes por nombre con los DTO actuales. [[DEC-081]] propone la
  búsqueda autorizada y acotada; no se carga el listado clínico completo desde
  Agenda.
- La próxima revisión debe verificar con teclado/lector de pantalla el retorno
  de foco y los errores, y recorrer los casos de borrador sucio/conflicto,
  rechazo del POS, solicitudes concurrentes y paciente sin permiso de lectura.
- TypeScript, ESLint dirigido a agenda, clínica, venta y compras, y
  `git diff --check` pasaron el 2026-10-26. El lint integral no finalizó; build,
  tests y revisión manual accesible siguen pendientes.
- Una pestaña nueva en `http://localhost:3000/app` todavía sirvió navegación y
  dashboard en inglés y mostró `185000.00`, aunque los archivos del checkout
  contienen la presentación en español/es-PY. No se pudo inspeccionar el motor
  Docker: el CLI recibió `Access is denied` en su pipe. No se considera una
  validación visual de UX-002; la Story sigue `in-progress`.

## Verificación

La Story [[UX-001]] registra comandos, resultados y limitaciones. La revisión
manual utiliza PostgreSQL/Redis/MinIO de Docker y API local con datos demo; no
modifica ventas, caja, inventario ni registros clínicos. Se verifican estados de
búsqueda, navegación lista-detalle, menú móvil, cambio de apariencia e
ingreso/salida. No equivale a una auditoría completa WCAG ni a un E2E
financiero.

## Referencias de interacción

- [WAI-ARIA: diálogo modal](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/):
  foco contenido, Escape y retorno al invocador para las confirmaciones y el
  menú.
- [shadcn: Skeleton](https://ui.shadcn.com/docs/components/skeleton):
  placeholders con estructura durante la carga; se mantiene la implementación
  compatible con la versión y los tokens del proyecto.
